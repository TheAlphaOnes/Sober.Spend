## Product

Sober.Spend is an offline-first **pre-transaction** UPI layer: scan or type a payment → parse VPA/merchant/amount/MCC → categorize → score against monthly budget + category limits → show a risk screen → confirm → open UPI with the amount filled → record the expense.

Login is optional. SQLite is source of truth. Supabase is opportunistic sync.

## Stack (verified)

Expo 57 / RN 0.86 / TS 6 / Expo Router / expo-sqlite + Drizzle / Zustand / Supabase / Reanimated 4.5 / lucide / expo-camera. Path aliases: `@/*` → `src/*`, `@/db/*` → `db/*`. Scheme: `soberspend`.

## Data

Local tables in `db/schema.ts` (created with raw `CREATE TABLE IF NOT EXISTS` on import):

- `expenses` — amount, **category name** (not id), merchant, note, ISO date
- `settings` — key/value (`monthly_budget`, `monthly_savings_target`, `savings_balance`, `categories_seeded`, `last_rollover_month`, `savings_deposits_YYYY-MM`)
- `categories` — name, color, icon, budget_limit, keywords JSON, sort_order
- `wishlist_buckets` / `wishlist_items` (status: funding | ready | bought)
- `vpa_category_map` — VPA → last chosen category

Supabase `0001` only has `expenses`, `categories`, `settings` + RLS. **No `profiles`, wishlist, or VPA tables** in that migration, despite HANDOUT claiming they exist.

## Stores

**auth** — session, email/password, `ensureProfile` upsert. On launch / sign-in / `SIGNED_IN` / `TOKEN_REFRESHED` it calls `fullSync()`. HANDOUT is stale here: it says sync is unused.

**budget** — monthly budget (default ₹30,000), savings target, persistent `savingsBalance`, monthly deposit counter. `addToSavings` / `deductFromSavings` move both wallet and month counter. `spendFromSavings` only hits the wallet (no double-count). `rolloverIfNeeded` once per month: leftover `budget − prevSpent − prevDeposits` goes into the savings pool.

**expense** — list + `pendingTransaction`. Confirm writes SQLite then clears pending. `resetCurrentMonth` deletes this month’s rows. `mergeRemoteExpenses` dedupes on `date|merchant|amount`. `clearAll` only clears Zustand, not SQLite.

**wishlist** — buckets + items. `buyItem`: if savings ≥ price → `spendFromSavings`; else `addExpense` as Other / “Wishlist purchase”. **No `fundItem` / `unfundItem`.** HANDOUT describes a funding pipeline that is not in the store. UI affordability is “can the whole pool cover the price?”, not per-item `funded_amount`.

## Engines

Categorize: VPA map → MCC ranges (Food/Travel/Entertainment/Bills/Shopping) → keyword includes → `"Other"`.

Decision: used = month expenses + monthly savings deposits. Category % uses category limit or monthly budget. Levels: exceeded if category ≥ 100%; near_limit if category ≥ 80% or monthly ≥ 90%; else safe.

UPI parse requires `upi://pay` + `pa`. Pay on decision builds a new `upi://pay?...` and `Linking.openURL`. `buildUPIDeepLink` exists but decision does not use it.

## Screens

Stack: index, scan (from bottom), decision (no gesture), profile, settings, history, categories, wishlist, auth-callback.

- **Dashboard** — `BudgetSummary` (spent includes savings deposits; overspend tilt + red spill), `RiskBanner` (BROKE/DANGER/WASTED/WARNING/SUS/SAFE/CHILL), savings card, category cards, last 6 txns, scan FAB. Risk copy in `index.tsx` is **not** the sample lines in HANDOUT.
- **Scan** — camera QR or manual. Uses `getIcon`. Fake scan: BigBazaar ₹1250 MCC 5411.
- **Decision** — category chips, before/after meter, Pay Up / Send It Anyway. Blocks if still on Other without override. Still has a **local 6-icon map**, not `getIcon`.
- **History** — sort + category chips, grouped dates.
- **Settings** — budget, allocation bar, savings add/withdraw, category limits, reset month, dev nuke (DELETE all local tables).
- **Categories** — add/delete, inline limit on blur.
- **Wishlist** — pool + buy/remove; add modal with optional URL.
- **Profile** — optional auth + stats. Cloud row says “Local storage active” even when signed in.

UI primitives: `NeoCard` (hard offset shadow + optional hatch), `NeoButton` / `NeoBackButton` (two-phase spring), `ProgressBar`, dashboard cards. Theme is neo-brutalist dark (`#0A0A0A`, accent `#C54770`, Jockey One + SignPainter).

**Sober.Spend** is an offline-first UPI budgeting app. The line is **“Spend Like Sober.”** It sits in front of a payment, not after it.

## The idea

A pot is a shared notebook, not a wallet. The app never holds money.

- **With a person** — you and Riya. Created when you confirm the first drop. Named after them.
- **With a crew** — Goa Trip, Flat 4B. You name it.

People toss **Drops** in. Everyone has one number:

| You see | Means |
|---|---|
| **You're in** | They owe you |
| **You're out** | You owe |
| **Even** | Boring. Nothing to do |

**Chip in** is “pay this person some or all of what you owe” — ₹100 now of ₹300 is normal, not a special case.

We stole Tricount’s two tabs (**Activity** / **Balances**) and Niptao’s last tap (open UPI, then mark paid). We refused Splitwise’s “simplify debts,” itemized receipts, and any escrow.

## How it feels

**Add a drop — one screen**

1. Dashboard **Pots** card, or Decision **Split this?**, or **Drop it** inside a pot.
2. Big amount. Who paid (default you). Who’s in (chips, default everyone). **Equal** or **Dutch**.
3. Equal: done. Dutch: type each person’s amount; leftover dumps on the payer; live “left to assign” bar like Settings.
4. Confirm.

That’s it. Category/merchant optional.

**Chip in — one sheet**

Tap the person on Balances → FULL / HALF / custom → UPI (prefilled) or cash. Always dated. Undo if you fat-fingered.

**People**

Pick from phone contacts. No account needed — they sit as a **guest**. Share a WhatsApp/SMS link tied to *that* guest. If they already use Sober.Spend, they hop in and see the same pot. If they sign up later with the same number, history follows them.

**Budget honesty**

If you paid the restaurant ₹1,200, your monthly budget records **your share** (₹300), not the whole bill. Money they chip back to you is not income. Money you chip to them is not a second expense.

## Mental math (the whole model)

A pays ₹1,200 for 4 people equal → A **+900**, others **−300**.  
B chips in ₹100 → B **−200**, A **+800**.  
Row written with time of the drop and time of the chip-in.

## What v1 will not have

Item-wise bills, recurring group rent, comments, charts, multi-currency, debt graphs, savings mixed with roommate payback, History → split (that’s v1.1).
